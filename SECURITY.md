# Security policy

## Supported versions

Only the latest release receives security fixes. Xolo is under active
development; if you run an older version, upgrade before reporting.

## Reporting a vulnerability

Do not open a public issue for a vulnerability.

Report it privately through
[GitHub private vulnerability reporting](https://github.com/xolo-gateway/xolo/security/advisories/new).
If that is not an option, write to wpetit@cadoles.com with `[SECURITY]` in the
subject line.

Include what you can: affected version or commit, reproduction steps, impact
as you understand it. A proof of concept helps but is not required.

## Who handles reports

Reports are handled by a restricted security team that includes at least one
authorized representative of each consortium member company (see
[GOVERNANCE.md](GOVERNANCE.md)). Information about an unpublished
vulnerability is confidential and stays under embargo until the advisory is
published; it is never used or referenced, commercially or otherwise, before
disclosure.

## What to expect

- Acknowledgment within 5 business days, qualification within 10.
- We investigate, keep you informed, and credit you in the advisory unless you
  prefer otherwise.
- Coordinated disclosure: we ask for 90 days from the report before public
  disclosure, less if a fix ships earlier, negotiable if a fix needs more time.
- The project publishes security advisories for official releases; each
  distributor remains responsible for the binaries, images, and hosted
  services it ships.

There is no bug bounty program.
